# 题库文档 → 交互式答题网页

把题库文档解析为结构化题目（题干、选项、正确答案），逐题撰写中文详解，最终产出**单文件、零依赖、可离线双击打开**的 HTML 答题网页。

模板支持单选题与判断题（True/False）。多选题只有在另外实现并验证多选提交、集合判分及相应解释后才可交付，不能套用单一下标判分。不支持填空题与简答题——它们的判分逻辑不同，遇到时剔除并向用户说明。

## 核心原则

1. **答案绝不凭空编造**。每个正确答案都必须能说出来源（文档标记 / 公式核算 / 学科判定），并在交付时分类报数。
2. **交付必须说明数据情况**。题量、去重情况、答案来源分布、剔除的题目及原因，全部如实告知。
3. **先探查再解析**。题库文档（尤其教学系统导出的）排版通常很脏，不要凭前几行猜结构就写解析器。

## 工作流

### 第 1 步：探查文档结构

PDF 先提取文字；扫描件须渲染逐页查看或使用可用 OCR，并核对选项和题号。HTML 读取其题目数组及交互代码，区分显式答案字段与用户选中状态。其他格式使用当前环境可用的对应读取工具，不依赖未安装技能。

docx **不要只用 Markdown 转换结果**——转 md 会丢掉列表结构、编号属性和表格边界，导致选项与题干粘连。必须先跑结构探查脚本：

```
python <skill-root>/scripts/probe_docx.py "<题库.docx>"
```

脚本输出：题号标题的分布与编号重启点（判断文档是否为多份题库拼接）、选项的三种排版形态（表格型 / 带 a.b.c.d. 前缀型 / 靠空行分隔型）、判断题 `True  False` 合并行的数量，以及**格式标记统计**（高亮色、字体色、加粗的出现次数）。

看清这些再写解析器。详细的排版模式识别与常见陷阱见 `references/docx-structure-parsing.md`。

### 第 2 步：定位正确答案的来源

按优先级依次尝试，**每条都要先验证再采信**：

1. **文档明确答案字段、答案文字或经验证的格式标记**。截图中的选中、Saved、蓝色背景只表示用户操作，不等于正确答案。黄色高亮、特定字体色、题号后附带答案字母（如 `Question 35  c`）都可能是答案标记。
   - 验证方法：统计每个题块被标记的选项数量。**必须绝大多数题块恰好标记 1 个选项、且没有题块标记多个**，才能确认该标记语义就是「正确答案」。若标记数分布散乱（有的 0 个、有的 3 个），说明标记是强调而非答案，不可采信。
   - 注意标记可能只在部分题块上，覆盖不全属正常。
2. **可核算的计算题**。按题目给出的数据套用学科公式算出结果，与选项比对，命中即确定答案。详解里必须附完整计算步骤。
3. **学科原理判定**。基础概念题、定义题按学科共识判定。
4. 以上都无法确定的题目 → **剔除**，并在交付说明中列出剔除数量与原因。

同一道题在文档不同副本中标记互相矛盾时（真实冲突，通常极少），按学科原理判定，并在交付说明中写明判定依据。

### 第 3 步：解析与去重

用 `python-docx` 或直接解析 `word/document.xml`（无依赖，推荐）。切分规则按探查结果写，不要套用通用假设。

**去重是本步的关键，务必按下面做**：

- 教学系统导出的题库常把同一批题重复导出多次，且**重复副本的选项顺序会被打乱**。
- 聚类键必须是「归一化题干 + 排序后的选项文本集合」，不能只用题干——否则选项顺序不同的同题会被判成不同题，或选项集合相同但题干不同的题被错误合并。
- **投票必须按选项文本，不能按选项位置**。按位置投票会把「顺序被打乱的同一答案」误判成冲突。
- 归一化：统一全角/半角、弯引号/直引号、不间断空格，去掉大小写与非字母数字字符后再比较，以吸收拼写差异（如 `characterisitics` / `characteristics`）。

去重后校验：每题至少 2 个选项、答案下标在选项范围内、题干非空、选项无重复。

**题干换行要保留**。含多行数据（财务数据、交易清单）的题干如果压成一行会无法阅读。解析时按原始段落结构保留换行，网页用 `white-space: pre-wrap` 渲染。

**清洗残留**：分区标题（如 `TOPIC 1 - INTRODUCTION TO ACCOUNTING`）、页脚统计（`Practical 10` / `Theory 22`）、粘连进题干的选项字母、题号前缀，都要从题干和选项中剥离。

### 第 4 步：题意解读、逐项解析与分类

题干与选项保留原语言，分析用简体中文。每题填写：

- `analysis`：作答后答案解析中的第一部分题意解读，约 40–100 字。解释题目在问什么、关键条件、关键词和正向/反向要求。出现 not、false、except、least 时明确提醒“选不成立/不符合的项”。作答前不展示题意解读；作答后先解释题目要求，再分析各选项。
- `optionExpl`：与 `opts` 同长度、同顺序的解释字符串数组。每项约 30–100 字，解释该项的概念、与题干条件的关系，以及为什么符合或不符合本题要求。所有选项必须覆盖，不只分析正确项或少数干扰项。
- `expl`：可选的知识点总结，避免简单重复逐项解析。计算题列出完整推导，沿用题中数字。
- `category`：具体而稳定的课件主题或知识点名。优先使用原课件明确的章节；没有课件证据时按内容归纳，如“营销环境”“市场研究与数据”，不得编造 Lecture 编号、页码或归属。`source` 保留原文件名、真实题号及已验证页码。

逐项解析不显示“符合本题要求 / 不符合本题要求”等重复标签，只在选项名称后使用简洁的绿勾或红叉，直接写推理说明：反向题中的正确选项可能本身是一句错误陈述，必须解释它为什么满足“选错误项”的要求。遇到“以上全部”时，各单项可以陈述成立，但须说明单独选择不够完整。

术语首次出现括注英文。不要编造数字、准则、讲义内容或为错误答案强行合理化。发现答案冲突或同义选项造成歧义时，按来源规则复核并披露，不确定时不要装作唯一正确。

题量较大时可按每批 50 题并行生成结构化 JSON；每批包含题意、逐项解析和分类，说明答案下标含义及学科背景。合并时验证每题 id 唯一且全覆盖、选项解释数组长度及顺序一致；遇到有依据的答案疑点应回报主 agent，不应要求“答案不可质疑”。

### 第 5 步：生成网页

读取 `assets/quiz-template.html`，替换两个占位符：

- `__TITLE__` → 页面标题（如「会计 Quiz 1 · 答题练习」）
- `__PAYLOAD__` → 题目 JSON 数组

JSON 元素结构：

```json
{"i":0,"stem":"Which statement is false?","opts":["选项A","选项B"],"ans":1,"analysis":"本题要选不成立的陈述，先核对每项是否符合给定条件。","optionExpl":["该项陈述成立，因此不符合本题选择错误陈述的要求。","该项违背定义，因此符合本题选择错误陈述的要求。"],"expl":"知识点总结","category":"知识点名称","source":"已验证的来源","src":"marked"}
```

- `ans` 是正确选项**下标**（0=A）。
- `src` 标记答案来源：`marked`（文档标记）/ `computed`（公式核算）/ `judged`（学科判定）。模板会在题号旁显示来源角标，便于用户重点复核非文档标注的题。

嵌入 JSON 时必须把 `</` 替换为 `<\/`，否则题目文本中出现 `</` 会提前终止 `<script>` 导致整页白屏。所有用户可见文本经 `esc()` 转义后再插入 DOM。

**替换占位符前先确认它在模板中只出现一次。** 若模板注释里写了 `__PAYLOAD__` 字面量做说明，全文 `replace` 会把整份 JSON 注入两次，文件体积翻倍（实测 162 KB → 321 KB）。用 `tpl.count("__PAYLOAD__") == 1` 断言，或只替换 `const DATA = __PAYLOAD__;` 这一整行。

**升级已交付的网页时，必须沿用原 `localStorage` 键名。** 模板默认键是 `quiz_web_progress_v1`，若旧页面用的是别的键名，直接套用模板会让用户已有的答题记录全部失效。升级前先读出旧页面的键名并替换回去；同时校验新旧题目**下标与内容完全一致**（进度按题目下标存储，题目增删或重排会导致记录错位到别的题上）。若题目确有变动，应换新键名让用户从头开始，不要留下错位的记录。

### 第 6 步：验证与交付

生成后**必须**验证，不能只看写入成功：

1. 用正则从 HTML 中抽回 `const DATA = [...]`，还原 `<\/` 后 `json.loads`，确认题目数量、每题答案下标有效、详解非空。这一步能同时证明 JSON 合法且未被 `</` 破坏。
2. 若 `apps-builder` 技能可用，跑其静态完整性检查脚本；否则至少确认：无 `__PAYLOAD__` 残留、`</script>` 只出现 1 次、模板引用的 DOM id 全部有定义。
3. 使用当前环境提供的文件链接或文件交付工具交付单个 HTML，不依赖不存在的专有工具。更新技能时一并交付包含 SKILL.md、模板和支持资源的 ZIP。
4. 浏览器实测：拖选选项文字可得到真实选区且不判分；整行点击支持鼠标和键盘，字母、文字、留白均能作答；答后文字仍可复制；作答前不展示解析，作答后解析按题意分析→逐项分析的顺序展开；知识点、年份（存在时）和答题状态组合筛选、跨分类题号跳转、原地展开及刷新恢复均正常。升级已有网页保留原路径、题序、答案对应及存储键，并用预置作答记录验证兼容。
5. 验证 `analysis` 非空、`category` 非空、`optionExpl` 数量与选项一致，人工检查反向题和“以上全部”题的逐项解释，不能只验证字符串长度。

交付说明必须包含：最终题量、原始题块数与去重情况、答案来源分类计数（文档标记 / 公式核算 / 学科判定各多少题）、剔除的题目数与原因、网页功能说明。**答案来源分类计数尤其重要**——它让用户知道哪些题的答案来自原文档、哪些是 AI 判定的，可据此决定复核重点。

## 交互与视觉标准（模板已实现，勿随意改动）

- 整行选项可点击作答，包含字母、文字及留白，不额外设置“选此项”按钮。文本设置 `user-select:text` 与 `-webkit-user-select:text`，拖选和复制不得误判分；按指针移动距离区分点击与拖动。使用 role、tabindex、aria-disabled 支持键盘，作答后锁定但文字仍可选中。
- 点击选项任意位置即刻判分：正确项标绿打勾，错选标红打叉，其余选项淡化；该题锁定不可再改。
- 判分后下方展开详解面板：答对显示「✓ 回答正确」，答错显示「✗ 回答错误」+ 你的选择 + 正确答案 + 详解正文。答对时不显示「你的选择」行（冗余）。
- 题意分析属于答案解析，不放在作答前的题干和选项之间。作答后按“题意分析→选项逐项分析→答案反馈与知识点总结→来源”的顺序展开。
- 顶部提供知识点分类和答题状态组合筛选；若来源含年份则可再按年份筛选。显示当前可见题量，题卡显示类别。统计保留全库总量，避免把筛选数当总成绩。
- 顶部吸顶统计条：总题数、已作答、答对、答错、正确率、进度条。
- 筛选：全部 / 未作答 / 答错 / 答对。
- 题号跳转：输入题号滚动定位并高亮闪烁；当前处于筛选状态时先重置答题状态、知识点及年份筛选，再跳转。
- 作答进度存 `localStorage`，关闭重开不丢；重置需 `confirm` 二次确认。
- 作答后**原地替换该题卡片**，不要整列表重渲染。在筛选状态下作答时，若立即重排列表会让题目瞬间消失、详解闪退看不到——这是必须避免的缺陷。筛选结果在用户切换筛选条件时才更新。
- 视觉：浅色卡片式，圆角 16px，柔和阴影，答对绿 / 答错红语义色，移动端自适应。

模板已实现全部上述行为，直接复用；只在用户明确要求时调整样式。

解析视觉：使用中性白底、清晰留白和轻分隔线。题意分析在前，选项解释以选项原文及其后的绿勾或红叉引导；正误颜色集中用于选中状态和总体反馈，不将整片解析染红或染绿。

解析排版采用三个连续区块：“题意分析”“选项解析”“知识总结”，每个区块正文仅一段。选项解析不显示 A/B/C/D 编号，不做逐项卡片或分隔行；将选项原文与对应解释依次连成一段，在应选选项名称后标绿色 ✓，非应选选项名称后标红色 ✗。反向题中符号表示是否应该选择该项，解释仍须区分陈述真伪与题目要求。答题区保留原选项字母、整行点击和文字拖选功能。
